## Review Findings — Standards

Treat these as remediation obligations until independently disproven with code/command evidence.

### STD-1 — CRITICAL

Filtered native fusion falls back to completely unfiltered manual RRF.

`hybrid_query()` catches `PyMongoError` and calls `_manual_rrf_search()` without `filter_config`; the manual vector and text pipelines contain no filters. This can violate tenant/ACL/evidence boundaries.

### STD-2 — HIGH

Explicit score fusion silently degrades to manual rank fusion after `PyMongoError`.

Score intent must hard-fail unless an explicit public fallback policy is designed later.

### STD-3 — HIGH

`_get_vector_context()` catches broad exceptions and returns `[]`, swallowing the required MongoDB 8.3 score-fusion error and other explicit option/capability failures.

### STD-4 — HIGH

Public filters use `value: Any` with `arbitrary_types_allowed=True`. Unsupported values can reach BSON/MongoDB instead of failing before execution.

### STD-5 — HIGH

File-wide Pyright directives suppress broad categories across `operate.py` and `mongo_impl.py`, including newly edited retrieval interfaces.

### STD-6 — HIGH

`explain_query()` is an untyped dictionary and omits required capability/version, timing, explain, and score metadata.

### STD-7 — LOW

All seven tickets say complete while every acceptance checkbox remains unchecked.

### STD-8 — LOW

Tests cover native happy paths and direct storage gates but not filtered fallback, score fallback, or public propagation of the 8.3 error.

## Required Remediation Order

### R1 — Fail-closed retrieval boundary

TDD first:

1. Force native aggregate to raise `PyMongoError`.
2. Prove current fallback drops filters (RED).
3. Pass `filter_config` into `_manual_rrf_search()`.
4. Compile MQL only for `$vectorSearch.filter`.
5. Compile Atlas syntax only for `$search.compound.filter`.
6. If equivalent filtering cannot be guaranteed, fail closed.
7. Restrict manual RRF fallback to rank-fusion requests.
8. Score-fusion failure must propagate a stable error.
9. Stop public query paths from swallowing capability/validation errors.

Acceptance:

- Zero unfiltered results under filtered fallback.
- Zero silent score-to-rank substitution.
- Public SDK/API receives MongoDB 8.3+ error on 8.2.

### R2 — Typed, bounded filter contract

- Replace `Any` with an explicit scalar union.
- Support string, finite numeric, boolean, timezone-aware date/datetime if retained, BSON ObjectId, UUID, and explicit null semantics.
- Restrict `in`/`nin` to non-empty bounded scalar lists.
- Reject mappings, arbitrary objects, non-finite numbers, malformed paths, and wrong operator/value shapes.
- Bound predicates, list lengths, field lengths, value lengths, and serialized request size.
- Add JSON-safe ObjectId/UUID representation and normalization shared by both HTTP APIs.
- Add property-based and oversized-input tests.

### R3 — HTTP parity and error hygiene

- Share request validation across lean/engine models.
- Align supported combinations and error shapes.
- Support filter/fusion with context and references through one retrieval execution.
- Make streaming support/rejection consistent and documented.
- Return allowlisted public validation errors only.
- Treat unexpected backend `ValueError` as generic internal failure.

### R4 — Complete typed diagnostics

Add exported, versioned models:

- `QueryExplanation`
- `SearchIndexStatus`
- `SearchIndexState` (`missing`, `building`, `ready`, `failed`, `unknown`)

Explanation must include effective mode/strategy, pipeline or server explain document, index identities, MongoDB version/capabilities, score-detail availability, timing, warnings, and stable schema version.

Index status must reconcile expected indexes and synthesize `missing`.

### R5 — Complete quantization lifecycle

- Explicit apply acknowledgement.
- Previous definition/rollback material.

### R6 — Complete schema validation
